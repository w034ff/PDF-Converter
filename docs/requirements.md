# 要件定義書

アプリ名は「PDF Converter」とする。

## 1. 目的

オンラインの PDF 変換サービス（例: iLovePDF）にファイルをアップロードせず、手元の PC だけで画像と PDF を相互に変換できるデスクトップアプリを作る。GitHub で公開し、誰でも利用・ビルドできる状態にする。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| 画像→PDF | 画像 1 枚を 1 ページとする PDF を作ること（複数ページの TIFF は、ページごとに 1 ページとする） |
| 結合 | 複数の画像を、指定した順に 1 ページずつ並べた 1 つの PDF にすること |
| PDF→画像 | PDF の各ページを描画（ラスター化）し、ページごとに画像ファイルとして保存すること |
| 解像度 | PDF→画像で、ページの 1 インチを何ピクセルで描くか（dpi） |
| 一括変換 | 1 つのフォルダ内の対応ファイルをまとめて変換し、指定フォルダへ保存する操作 |

## 3. スコープ

### 3.1 対象

- 画像（PNG / JPEG / WebP / BMP / TIFF）から PDF への変換（1 枚ずつ、結合）。出力は長期保存用の PDF/A-2b にもできる
- PDF から画像（PNG / JPEG / WebP）への変換（全ページ、ページの範囲指定、カラーとグレースケール）
- 単体の変換と、フォルダ単位の一括変換
- Windows と Linux 向けのデスクトップアプリ（Tauri 2）
- 日本語と英語の UI
- GitHub Releases でのバイナリ配布

### 3.2 初回リリースの対象外（後の版で検討する）

初回リリースには含めない。完成後の版上げで、要件を追加して取り組む候補とする。

- PDF の編集（ページの並べ替え・削除・回転、PDF どうしの結合・分割、注釈、フォーム入力）
- OCR（画像の文字を検索できる PDF にする機能）
- GIF / AVIF / HEIC / SVG の入力、PNG / JPEG / WebP 以外の出力
- PDF/A-2b 以外の規格への準拠（PDF/A-1・A-3・A-4、PDF/UA など）、PDF の圧縮率の調整
- サブフォルダの再帰的な一括変換
- コード署名
- macOS、ARM64、モバイル
- CLI 版

### 3.3 対象外

- 自動アップデート（アプリが通信しないこと（NFR-01）と両立しないため）

## 4. 利用環境

| 項目 | 要件 |
| --- | --- |
| Windows | Windows 10 / 11（x64）。WebView2 ランタイムがない環境ではインストーラーが導入する |
| Linux | x64、WebKitGTK 4.1 が利用できるディストリビューション（Ubuntu 22.04 以降相当） |
| ネットワーク | 不要。アプリは一切通信しない |

## 5. 機能要件

優先度は Must（初回リリースに必須）/ Should（初回リリースに含めたい）で示す。

### FR-01 入力（Must）

- 「画像→PDF」と「PDF→画像」は画面を分け（タブ）、それぞれ変換するファイルを一覧に集めてから変換する。単体の変換、結合、一括変換は、どれもこの一覧で行う。
- 一覧には、ファイル選択ダイアログ（複数選択可）、フォルダ選択ダイアログ、ドラッグ&ドロップ（ファイルとフォルダ）でファイルを追加できる。一覧から個別に外す操作と、すべて外す操作がある。
- フォルダを追加したときは、その直下にある対応拡張子のファイルだけを追加し、サブフォルダは見ない。
- 追加しようとしたもののうち、対応しない形式のファイルとサブフォルダは追加せず、その件数を表示する。
- 画像の対応形式は PNG / JPEG / WebP / BMP / TIFF、拡張子は `.png` `.jpg` `.jpeg` `.webp` `.bmp` `.tif` `.tiff`。PDF の拡張子は `.pdf`。いずれも大文字小文字を区別しない。
- 拡張子が対応していても中身を読めない場合は、そのファイルをエラーとして扱う。
- 複数ページの TIFF は、1 つのファイルとして一覧の 1 行に入れ、ページ数を表示する。並べ替えと削除はファイルの単位で行う。
- TIFF のうち、CMYK の色やファクスの G3 の圧縮など、読まない種類のものは非対応の形式として扱う。1 つのページでも読まない種類なら、ファイル全体を非対応とする。読む種類は詳細設計で定める。
- 総ピクセル数が上限を超える画像（TIFF はどれか 1 つのページが超えるもの）、ページ数が上限を超える PDF と TIFF はエラーとして扱う。上限値は詳細設計で定め、名前付き定数にする。

### FR-02 画像→PDF（Must）

- 画像を画質を落とさずに PDF に入れる。JPEG は再圧縮せずに画像のデータをそのまま入れ、それ以外は可逆の圧縮で入れる。TIFF は画素に戻してから可逆の圧縮で入れる（JPEG の圧縮を使う TIFF も同じで、画質は変わらないがファイルは大きくなる。白黒の TIFF も元のファイルより大きくなる）。元の画像のメタデータは入れない（NFR-01）。
- 透過（アルファチャンネル）を持つ画像は、PDF でも透過のままにする。
- JPEG の向きの情報（EXIF Orientation）と TIFF の向きの情報（Orientation）に従って、正しい向きのページにする。
- 複数ページの TIFF は、全ページを順に PDF のページにする。「1 枚ずつ」では、1 つの TIFF から全ページを持つ 1 つの PDF を作る。1 つのページでも読めなければ、その TIFF 全体を失敗とし、ほかのページも入れない（ページが抜けた PDF を作らないため）。
- ページの大きさは「画像と同じ大きさ」と用紙（A3・A4・A5・B4・B5・Letter・Legal。B 判は JIS の寸法）から選べる。用紙のときは、向きを「自動（縦横は画像に合わせる）」「縦」「横」から選べる。「画像と同じ大きさ」の場合に 1 ピクセルを何ポイントにするかは詳細設計で定める。横と縦の解像度が違う画像（ファクスの TIFF など）は、横と縦をそれぞれの解像度で計算し、見た目の縦横比を保つ。
- 保存ダイアログで保存先を選んで保存する。初期ファイル名は元画像のファイル名の拡張子を `.pdf` に替えたもの。
- 出力を長期保存用の PDF/A-2b にできる（既定は通常の PDF）。1 枚ずつと結合のどちらにも使える。PDF/A では CMYK の画像を使えず、その画像はエラーにする（FR-09）。CMYK の扱いを広げるかは、求める声が出てから決める。

### FR-03 結合（Must）

- 複数の画像を選び、並べ替え・削除してから 1 つの PDF にできる。並べ替えはマウスとキーボードの両方でできる。
- 各ページの作り方は FR-02 と同じ。
- 初期ファイル名は、先頭の画像のファイル名の拡張子を `.pdf` に替えたもの。

### FR-04 PDF→画像（Must）

- PDF のページ数を表示し、全ページまたはページの範囲（例: `1-3, 5`）を指定して変換できる。
- 複数の PDF をまとめて変換するときは、指定した範囲を全部の PDF に当てはめる。範囲の一部のページがない PDF は、あるページだけを変換する。範囲のページが 1 つもない PDF は、失敗とは別に「対象のページなし」として表示する。
- 出力形式は PNG、JPEG、WebP から選べる。JPEG の品質の値は詳細設計で定める。WebP は可逆の圧縮で書く。
- 色はカラーとグレースケールから選べる。
- 解像度を選べる。よく使う値の選択肢に加えて、範囲の中の任意の整数を指定できる。選択肢、範囲、既定値は詳細設計で定める。
- 透過を持つページを PNG で出力する場合、背景を白にするか透過にするかは詳細設計で定める。
- 保存先のフォルダを選び、ページごとに `元の名前_p001.png` のような名前で保存する。桁数と区切りは詳細設計で定める。
- 同名のファイルがすでにある場合は上書きせず、`name (1).png` のように番号を付けて保存する。
- 変換中は進捗（完了ページ数 / 全ページ数）を表示し、キャンセルできる。
- パスワードで保護された PDF は、パスワード（閲覧または所有者のパスワード）を入力すると変換できる。同じパスワードで開けるほかの PDF も、あわせて開く。入力したパスワードは保存しない。

### FR-05 一括変換（Must）

- 「画像→PDF」で「1 枚ずつ」を選んだとき、および「PDF→画像」で一覧に PDF が複数あるときは、保存先のフォルダを 1 つ指定し、一覧のファイルをまとめて変換する。
- 変換の設定は、開始した時点の設定を全ファイルに使う。変換中は設定と一覧を変えられない。
- 出力名の重なりは FR-04 と同じく番号を付けて避ける。
- 進捗の表示、キャンセル、1 ファイルの失敗で全体を止めないこと、終了時の成功・失敗の件数と理由の表示は、SVG Tracer の一括変換と同じ振る舞いにする。
- キャンセルしたとき、書き込み途中の不完全なファイルを保存先のフォルダに残さない。

### FR-06 プレビュー（Should）

- PDF→画像で、ページのサムネイルを表示し、範囲指定の確認に使える。
- 結合で、並べた画像のサムネイルを表示する。

### FR-07 多言語対応（Must）

- UI を日本語と英語で表示できる。エラーメッセージも両言語で用意する。
- 初回起動時は OS の言語設定が日本語なら日本語、それ以外なら英語で表示する。アプリ内で切り替えられ、次回起動時も切り替えた言語を使う。

### FR-08 ライセンス表示（Must）

- 「このアプリについて」画面で、バージョン、本アプリの MIT ライセンス、同梱している第三者ライブラリ（PDF の描画エンジンを含む）のライセンス一覧を表示する。

### FR-09 エラー表示（Must）

- 次の場合に、原因が分かるメッセージを表示する: 非対応形式、読み込みの失敗（壊れたファイル）、パスワードで保護された PDF、パスワードの誤り、画像サイズ・ページ数・描画サイズの上限超過、書き込みの失敗（権限不足、ディスク容量不足など）、PDF/A で使えない画像（CMYK）。
- エラーでアプリを終了させず、別のファイルを選び直せる状態に戻る。

### FR-10 設定の保持（Should）

- 最後に使った変換の設定（ページの大きさ、用紙の向き、PDF/A、出力形式、色、解像度など）と一括変換のフォルダを、次回起動時に復元する。

## 6. 非機能要件

### NFR-01 セキュリティ・プライバシー

- アプリは外部と一切通信しない。テレメトリ、自動アップデート確認、外部リソースの読み込みを含めない。Content Security Policy で外部への接続を禁止する。
- Windows の WebView2 ランタイム自身が行う通信の扱いは、SVG Tracer と同じにする（止められるものは止め、止められないものは README に明記する）。
- Tauri の capabilities は必要最小限にする。ファイルの読み書きは、ユーザーがダイアログまたはドラッグ&ドロップで選んだファイル・フォルダに限る。
- 出力に、利用者が意図しない情報を持ち込まない。画像→PDF では、元の画像のメタデータ（EXIF の位置情報・撮影日時・機種、XMP、IPTC、コメント、埋め込みの縮小画像、JPEG の終わりより後ろのデータなど）を PDF に入れない。見た目に要る情報（色のプロファイルなど）だけを残す。PDF の文書情報には作成ソフトだけを入れ、元のファイル名やパスは入れない。消すかどうかは選ばせない。
- PDF は外から来た信頼できないファイルとして扱う。壊れた PDF や細工された PDF で PDF の読み込み・描画の処理が異常終了しても、アプリは終了しない。そのファイルを読み込みの失敗（FR-09）として表示し、続けて別のファイルを扱える。一括変換では、そのファイルを失敗として残りの変換を続ける。

### NFR-02 性能

- A4 の 1 ページを 150 dpi で画像にする処理が、基準環境で 1 秒以内に終わる（基準環境は詳細設計で定める）。
- 変換中も UI は操作可能で、キャンセル操作は 1 秒以内に受け付けられる。
- 大きな PDF や高い解像度でもメモリを使い切らない。1 ページの描画サイズに上限を設ける。

### NFR-03 変換品質

- 画像→PDF: PDF から取り出した画像が元画像と一致する（PNG / WebP / BMP / TIFF は画素が同じ、JPEG はメタデータを除いた画像のデータのバイト列が同じ）。
- PDF→画像: テスト用の PDF を描画した結果が、基準の画像と一定以上一致する。一致度の算出方法としきい値は詳細設計で定める。
- 出力した PDF は、一般的な PDF ビューアー（ブラウザー内蔵のものを含む）で開ける。
- PDF/A を選んだ出力は、PDF/A の検証ツールで PDF/A-2b に合格する。ページの見た目は通常の PDF と同じになる。

### NFR-04 配布

- GitHub の公開リポジトリで MIT ライセンスとして公開する。
- GitHub Actions で Windows と Linux 向けにビルドし、GitHub Releases に添付する（Windows: MSI と NSIS、Linux: AppImage と .deb）。
- コード署名は行わない。README に Windows SmartScreen の警告が出ることを記載する。

### NFR-05 ライセンス管理

- 依存ライブラリのライセンスは、MIT のアプリにバイナリで同梱できるものに限る。GPL / AGPL のライブラリは使わない。
- 第三者ライセンス一覧はビルド時に自動生成し、手作業で管理しない。同梱するネイティブのライブラリ（PDF の描画エンジンなど）も一覧に含める。
- CI で依存ライブラリのライセンスを検査し、許可リスト外のライセンスが混入したらビルドを失敗させる。

### NFR-06 品質・保守

- Rust の変換処理とフロントエンドのロジックに自動テストを用意し、CI で Windows と Linux の両方で実行する。
- テスト用の画像と PDF（フィクスチャ）はリポジトリに含める。
- 既知の脆弱性の検査と依存の更新の自動化は SVG Tracer と同じ仕組みにする。同梱するネイティブのライブラリは Dependabot の対象外なので、更新の確認方法を詳細設計で定める。

### NFR-07 使いやすさ・外観

- 主要な操作はキーボードだけでも行える。
- ライト / ダークの配色を持ち、OS の設定に従って切り替わる。
- ウィンドウの最小サイズを定め、それ以上のどのサイズでも操作部品が重ならない。
- 高解像度ディスプレイ（表示倍率 100%〜200%）で文字やアイコンがぼやけない。

## 7. 受け入れ基準

初回リリースは、次をすべて満たしたときに受け入れる。

1. FR-01〜FR-05、FR-07〜FR-09 の Must 要件について、詳細設計で定めるテストがすべて合格する。
2. 画像→PDF: 透過の PNG / WebP、RGB と CMYK の JPEG、EXIF の向き付きの JPEG、16 ビットの PNG、BMP を、「画像と同じ大きさ」と「A4」の両方で PDF にし、NFR-03 を満たす。結合で、並べ替えた順にページが並ぶ。位置情報などのメタデータを持つ JPEG の PDF に、元のメタデータが残らない（NFR-01）。TIFF（複数ページ、白黒のファクス（横と縦の解像度が違うもの）、グレー、RGB、透過、16 ビット、色の表を持つもの、JPEG の圧縮）も同じく PDF にし、全ページが順に入る。CMYK と G3 の TIFF は非対応の形式になる。PDF/A を選んで、CMYK の JPEG 以外の上の画像を 1 枚ずつと結合で PDF にし、PDF/A-2b の検証に合格する。CMYK の JPEG はエラーになる。
3. PDF→画像: テスト用の PDF を PNG と JPEG、72 / 150 / 300 dpi で画像にし、NFR-03 を満たす。ページの範囲の指定（1 つの PDF、複数の PDF、範囲の一部のページがない PDF、範囲のページが 1 つもない PDF）が FR-04 のとおりに働く。
4. 次の異常系で FR-09 のとおりにエラーが表示され、アプリが操作可能なまま残る。
   - 中身が壊れた画像と PDF
   - パスワードで保護された PDF（制限だけを掛けた暗号化の PDF は開ける）
   - 上限を超える画像・ページ数・描画の大きさ
   - PDF の処理が異常終了・時間切れになった場合（テスト用の仕組みで起こす）
   - 書き込み権限のない保存先のフォルダ
5. 出力名が重なるケース（既存のファイルとの重複、同じ変換の中での重複）が、番号付きの別名で保存される。
6. 一括変換を途中でキャンセルしたとき、保存先のフォルダに不完全なファイルが残らない。
7. Windows と Linux の両方で、GitHub Actions がビルドしたインストーラーからインストールして起動し、上記 2〜6 を手動で確認できる。
8. アプリの実行中に外部への通信が発生しない（NFR-01 の例外を除く）。
9. CI のライセンス検査が通り、「このアプリについて」画面に、pdfium と同梱のライブラリを含む第三者ライセンス一覧が表示される。

## 8. 事前検証（スパイク）で決めること

- PDF の描画エンジン: pdfium（`pdfium-render`、OS ごとにライブラリを同梱）と hayro（純 Rust）を、描画の正確さ、速さ、配布のしやすさで比べて選ぶ
- 描画エンジンを別プロセスで動かす必要があるか（NFR-01 の「アプリ全体が終了しない」を満たす方法）
- PDF を書く crate: krilla、pdf-writer、printpdf、lopdf などから、JPEG のそのままの埋め込み、透過、ページの大きさの指定ができるものを選ぶ
- 次の入力の扱い: CMYK の JPEG、16 ビットの PNG、色のプロファイル付きの画像、EXIF の向き

## 9. 詳細設計で決めること

- 画面構成と画面遷移
- 「画像と同じ大きさ」のときの 1 ピクセルの大きさ、用紙での寸法・余白・配置
- 解像度の選択肢・範囲・既定値、JPEG の品質、出力ファイル名の形式
- 画像サイズ・ページ数・描画サイズの上限値
- PDF→画像の一致度の算出方法としきい値、性能の基準環境
- 設定の保存場所と形式
- Tauri の capabilities とコマンドの一覧
- 使用ライブラリとバージョン、同梱するネイティブのライブラリの更新方法
