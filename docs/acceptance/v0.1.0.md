## 範囲の外

- **Linux のドラッグ＆ドロップ**: `xdotool` ではファイルマネージャーからのドロップを再現できない。T07 でオーナーが WSLg の `pcmanfm` から落として確かめており、今回はオーナーの判断で行わない。
- **Linux の項目 2〜6 のうち上に書かなかった手順**（項目 2 の外す・Alt + ↑↓、項目 3 の 4b〜6、項目 5 など）: Windows で合格し、Linux とコードが同じ。

## 気づいた点（不合格ではない）

- **Windows**: 動作は問題ないが、UX の直す点がある（オーナー）。
- **Linux で保存したファイルの権限が `0600`**: 保存したすべての PDF と画像が `-rw-------` になる（umask どおりなら `-rw-r--r--`）。`save_atomic` が `tempfile` の一時ファイル（作成時に `0600`）をそのまま `persist` するため。同じユーザーで開くぶんには困らないが、ほかのユーザーと共有するフォルダなどでは読めない。
- **WSLg で `.deb` 版のウィンドウが出ない**: Mesa の `ZINK: failed to choose pdev`、`egl: failed to create dri2 screen` が出て、ウィンドウが出なかった。同じ PC の Xvfb では起動するので、WSL のグラフィックスの不調と見ている（再起動のあとに WSLg でもう一度確かめる）。
- **AppImage の初回の保存のダイアログ**: 保存先を一度も選んでいないとき、「PDF を保存」のダイアログが AppImage のマウント先（`/tmp/.mount_PDF…/usr`。読み取り専用）で開く。
- **手順書の `corrupt.png` の期待**: 上の項目 4 の備考のとおり、設計と違っていた。Windows でも、追加したときに「✕ 読み込めません」は出なかった（オーナー）。アプリは設計どおりとし、オーナーの判断で手順書のほうを今の動きに合わせて直した。
