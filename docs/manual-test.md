## 事前準備

### 1. 手動確認用ファイルの作成

リポジトリ直下で次のコマンドを実行し、フィクスチャに含まれない手動確認用ファイル（画素数上限超過画像、ページ数上限超過 PDF、キャンセル確認用多ページ PDF）を作業用フォルダに生成します。

```bash
npm run manual-test:files -- <出力先フォルダ>
```

これにより、次の 3 ファイルが生成されます:
- `too-many-pixels.png`: 80,010,000 画素（10,000 × 8,001）の画像（`MAX_IMAGE_PIXELS` 超過）
- `too-many-pages.pdf`: 10,001 ページの PDF（`MAX_PDF_PAGES` 超過）
- `many-pages.pdf`: 200 ページの図形 PDF（300 dpi での変換に開発用 PC で約 35 秒を要する多ページ PDF。PC の性能によって変わります）

### 2. フィクスチャの配置場所

リポジトリ内の `crates/core/tests/fixtures/` にあるテスト用ファイルを使用します（design §11.1）：
- `logo_alpha.png` / `logo_alpha.webp`: 透過背景の図形（透過の保持確認用）
- `photo.jpg`: 写真調の RGB JPEG（JPEG バイト列の無劣化保持確認用）
- `photo_cmyk.jpg`: CMYK の JPEG
- `rotate0.jpg`、`flip_h.jpg`、`rotate180.jpg`、`flip_v.jpg`、`rotate90_flip_h.jpg`、`rotate90.jpg`、`rotate270_flip_h.jpg`、`rotate270.jpg`: EXIF 向き 1〜8 の JPEG（向きの反映確認用）
- `deep16.png`: 16 ビットの PNG
- `opaque.bmp` / `alpha32.bmp`: 24 ビットおよび 32 ビットの BMP
- `dpi300.png` / `dpi300.jpg`: 解像度 300 dpi の情報付き画像
- `shapes.pdf`: 図形と画像で構成された 3 ページの PDF（A4 縦、A4 横、Letter）
- `encrypted.pdf`: 閲覧パスワード付き PDF
- `restricted.pdf`: 閲覧パスワードなし・権限制限付きの暗号化 PDF
- `corrupt.pdf` / `corrupt.png`: 壊れたファイル
- `mixed_sizes.pdf`: 3 ページの PDF（2 ページ目が 3000×3000 pt で 300 dpi 描画上限超過用）

### 3. 文字を含む実用 PDF

文字の描画を目視確認するため、確認者の手元にある一般的な PDF（文書や論文、マニュアルなど）を 1 つ用意します（第三者権利保護のためリポジトリには含めません）。

## 項目 2: 画像 → PDF（透過、各画像形式、EXIF 向き、16 ビット、BMP、ページの大きさ、結合・並べ替え）

要件: FR-02、FR-03、NFR-03。各種形式の画像を劣化なく PDF 化し、結合およびページの大きさの指定が正しく機能することを確認します。

### 準備（使うファイル）
- `logo_alpha.png`、`logo_alpha.webp`
- `photo.jpg`、`photo_cmyk.jpg`
- `rotate90.jpg`（または任意の EXIF 向き付き JPEG）
- `deep16.png`
- `opaque.bmp`、`alpha32.bmp`
- `dpi300.png`、`dpi300.jpg`

### 操作
1. アプリを起動し、上部バーの「画像 → PDF」タブを選択する。
2. 「画像を追加」またはドラッグ＆ドロップで、上記の各画像（計 10 ファイル）を追加する。
3. **画像に合わせる（結合）**:
   - 左パネルで「出力」を「1 つの PDF」、「ページの大きさ」を「画像に合わせる」にする。
   - 下部バーの左側に「10 ページの PDF になります」と表示されていることを確認する。
   - 「PDF を保存」をクリックし、保存ダイアログでファイル名（例: `fit_merged.pdf`）を指定して保存する。
4. **A4（結合）**:
   - 左パネルで「ページの大きさ」を「A4」に切り替える。
   - 「PDF を保存」をクリックし、保存ダイアログでファイル名（例: `a4_merged.pdf`）を指定して保存する。
5. **並べ替えと削除**:
   - 一覧の各行の「↑」「↓」ボタンをクリックするか、行をドラッグ＆ドロップして順序を入れ替える。また、キーボードのフォーカスを合わせて Alt + ↑ / ↓ で行が移動することを確認する。
   - 任意の 1 行の「外す」ボタンをクリックし、一覧から除外されることを確認する。
   - 再度「PDF を保存」を実行して保存する。
6. **1 枚ずつ（一括変換）**:
   - 左パネルで「出力」を「1 枚ずつ」に切り替える。
   - 準備の 10 ファイルがすべて一覧にある状態にする（手順 5 で外したファイルがあれば再度追加する）。
   - 空の保存先フォルダを用意し、「保存先フォルダ」の「フォルダを選ぶ」をクリックしてそのフォルダを指定する。
   - 下部バーの「変換を開始」をクリックする。

### 期待する結果
- 生成された PDF をブラウザー（Chrome / Edge / Firefox）等で開いて目視確認する:
  - `fit_merged.pdf`: 各ページの寸法が画像の寸法（画素数 ÷ dpi × 72 pt）と一致し、余白なくぴったり収まっている。
  - `a4_merged.pdf`: 各画像が A4（縦または横）の中央に余白（10 mm）を持って縦横比を保って収まっている。
  - 透過画像（`logo_alpha.png`、`logo_alpha.webp`）は透過が維持されている。この 2 つは、透明な画素の色の値が黒（RGB 0, 0, 0）なので、透過が失われると透明だった所が黒く出る。次の 3 つで見分ける:

    | 部分 | 透過が維持されているとき | 透過が失われたとき |
    | --- | --- | --- |
    | 背景 | 白（PDF の紙の色が透けて見える） | 黒 |
    | 上端の帯 | 左の白から右の青へだんだん濃くなる | 端から端まで同じ青 |
    | 右下の緑の四角（半透明） | 下のオレンジの円が透けて見える | 円が隠れた濃い緑 |

  - 透過の情報が PDF に入っていることを、PDF の中の `/SMask`（透過のある画像に付く）の数で確かめる。`fit_merged.pdf` と `a4_merged.pdf` は、どちらも **4**（透過のある `logo_alpha.png`、`logo_alpha.webp`、`deep16.png`、`alpha32.bmp` の 4 つ）になる:
    - **Windows**（PowerShell）:
      ```powershell
      (Select-String -Path .\fit_merged.pdf -Pattern '/SMask' -SimpleMatch -AllMatches).Matches.Count
      ```
    - **Linux**:
      ```bash
      grep -a -o '/SMask' fit_merged.pdf | wc -l
      ```
  - CMYK JPEG、16 ビット PNG、BMP が乱れなく正しい色で描画されている。
  - `rotate90.jpg` が回転せず正しい向きで表示されている。
  - 並べ替えた順序どおりに各ページが並んでいる。外した画像は PDF に含まれない。
- 「1 枚ずつ」の変換では、指定したフォルダ内に次の 10 個の PDF ファイルが保存される（同名ステムの拡張子違いは `(1)` の連番が付与される）:
  - `alpha32.pdf`
  - `deep16.pdf`
  - `dpi300.pdf`
  - `dpi300 (1).pdf`
  - `logo_alpha.pdf`
  - `logo_alpha (1).pdf`
  - `opaque.pdf`
  - `photo.pdf`
  - `photo_cmyk.pdf`
  - `rotate90.pdf`
- 変換完了時、一覧の上に「変換が終わりました：成功 10 件」のバナーが表示され、下部バーに「✓ すべて完了しました」と表示される。

## 項目 3: PDF → 画像（各形式・解像度、ページ範囲指定、複数 PDF 一括、文字を含む実際の PDF）

要件: FR-04、FR-05、NFR-03。PDF のページを PNG / JPEG 画像へ変換し、解像度やページ範囲の指定、複数 PDF の一括変換が正しく機能することを確認します。

※既存ファイルとの意図しない名前重複を避けるため、各手順でそれぞれ別の空フォルダを用意して保存先に指定してください。

### 準備（使うファイル）
- `shapes.pdf`（3 ページの図形 PDF）
- 確認者が用意した文字を含む実用 PDF

### 操作と期待する結果

#### 1. 準備
- 上部バーの「PDF → 画像」タブを選択する。

#### 2. 単一 PDF・全ページ変換（PNG / 150 dpi）
- 空の保存先フォルダ（例: `out_step2/`）を用意して指定する。
- `shapes.pdf` を追加する。単一 PDF モードになり、3 ページ分のサムネイルが表示される。
- 左パネルで「ページ」を「すべて」、「形式」を「PNG」、「解像度」を「150 dpi（標準）」にする。
- 下部バーの左側に「3 ページを PNG で保存します」と表示されていることを確認する。
- 「変換を開始」をクリックする。
- **期待結果**:
  - `out_step2/` に `shapes_p1.png`、`shapes_p2.png`、`shapes_p3.png` の 3 ファイルが生成される。
  - 背景が白で描画されている。
  - 上部バナーに「変換が終わりました：成功 1 件」、下部バーに「✓ すべて完了しました」と表示される。

#### 3. 解像度・形式の切り替え（JPEG / 300 dpi）
- 新たな空の保存先フォルダ（例: `out_step3/`）を用意して指定する。
- 左パネルで「形式」を「JPEG」、「解像度」を「300 dpi（印刷する）」に切り替える（「ページ」は「すべて」のまま）。
- 下部バーの左側に「3 ページを JPEG で保存します」と表示されていることを確認する。
- 「変換を開始」をクリックする。
- **期待結果**:
  - `out_step3/` に `shapes_p1.jpg`、`shapes_p2.jpg`、`shapes_p3.jpg` の 3 ファイルが生成される。
  - 各画像が手順 2 の 150 dpi PNG と比較して縦横それぞれ約 2 倍（画素数約 4 倍）の寸法になっている。

#### 4. ページ範囲の指定（サムネイル選択と手入力）

##### 4a. サムネイルクリックによる選択（PNG / 150 dpi、範囲 `1, 3`）
- 新たな空の保存先フォルダ（例: `out_step4a/`）を用意して指定する。
- 左パネルで「形式」を「PNG」、「解像度」を「150 dpi（標準）」に設定する。
- 左パネルで「ページ」を「範囲を指定」に切り替える。
  - 入力欄に初期値として `1-3` が入り、全 3 ページのサムネイルが枠で囲まれた選択状態になっていることを確認する。
- サムネイルの 2 ページ目をクリックして選択から外す。
  - 入力欄が自動的に `1, 3` に変化し、1 ページ目と 3 ページ目のみが選択状態になることを確認する。
- 下部バーの左側に「2 ページを PNG で保存します」と予告が表示されていることを確認する。
- 「変換を開始」をクリックする。
- **期待結果**:
  - `out_step4a/` に `shapes_p1.png` と `shapes_p3.png` の 2 ファイルのみが生成され、`shapes_p2.png` は生成されない。

##### 4b. 手入力による範囲指定（PNG / 150 dpi、範囲 `2`）
- 新たな空の保存先フォルダ（例: `out_step4b/`）を用意して指定する。
- 「形式」が「PNG」、「解像度」が「150 dpi（標準）」であることを確認する。
- 範囲入力欄に手入力で `2` と入力する。
  - 2 ページ目のサムネイルのみが選択状態になり、1 ページ目と 3 ページ目が選択から外れることを確認する。
- 下部バーの左側に「1 ページを PNG で保存します」と予告が表示されていることを確認する。
- 「変換を開始」をクリックする。
- **期待結果**:
  - `out_step4b/` に `shapes_p2.png` の 1 ファイルのみが生成され、`shapes_p1.png` や `shapes_p3.png` は生成されない。

#### 5. 文字を含む実用 PDF の描画確認（PNG / 150 dpi）
- 新たな空の保存先フォルダ（例: `out_step5/`）を用意して指定する。
- 見出し右側の「外す」ボタンをクリックして `shapes.pdf` を一覧から除外する。
- 確認者が手元に用意した文字を含む実用 PDF を追加する。
- 左パネルで「ページ」を「すべて」、「形式」を「PNG」、「解像度」を「150 dpi（標準）」にし、「変換を開始」をクリックする。
- **期待結果**:
  - 出力された各画像を開いて目視確認し、文字が欠けず、文字化けやレイアウト崩れなく鮮明に描画されていること。

#### 6. 複数 PDF の一括変換と範囲の適用（JPEG / 150 dpi、範囲 `2-10`）
- 新たな空の保存先フォルダ（例: `out_step6/`）を用意して指定する。
- 手元の PDF が入っている状態のまま、「PDF を追加」をクリックして `shapes.pdf` を追加する（画面が表形式の複数 PDF 一括モードになる）。
- 左パネルで「形式」を「JPEG」、「解像度」を「150 dpi（標準）」にする。
- 「ページ」で「範囲を指定」を選び、入力欄に `2-10` と入力する（3 ページの `shapes.pdf` には 2〜3 ページのみ存在し、4 ページ以降は存在しない）。
- 下部バーの左側に「PDF 2 件から {該当ページ数合計} ページを JPEG で保存します」と表示されることを確認する。
- 「変換を開始」をクリックする。
- **期待結果**:
  - 各 PDF から指定範囲内に存在するページ（`shapes.pdf` からは 2 ページと 3 ページ: `shapes_p2.jpg`、`shapes_p3.jpg`）のみが書き出され、存在しないページ（4〜10 ページ）はエラーにならずスキップされて正常完了する。
  - 表の各行の状態が「✓ 完了」となり、上部バナーに「変換が終わりました：成功 2 件」、下部バーに「✓ すべて完了しました」と表示される。

#### 7. 対象ページなしの確認（範囲 `999`）
- 新たな空の保存先フォルダ（例: `out_step7/`）を用意して指定する。
- 複数 PDF モードのまま、「範囲を指定」の入力欄に `999`（全 PDF のページ数を大きく超える番号）を入力する。
- 下部バーの左側に「範囲に当てはまるページがありません」と表示されることを確認する。
- 「変換を開始」をクリックする。
- **期待結果**:
  - 変換終了後、表の各行の状態に「対象のページなし」、理由に「指定した範囲のページがありません」が表示される。
  - 上部バナーに「変換が終わりました：成功 0 件 · 対象のページなし 2 件」が表示される。
  - 下部バーに「完了」と表示される。
  - 保存先フォルダにはファイルが 1 つも生成されない。

## 項目 4: 異常系のエラー表示（破損ファイル、パスワード保護、上限超過、権限不足、ワーカー異常終了・時間切れの自動テスト確認）

要件: FR-09、NFR-01。異常なファイルやエラー発生時に適切なメッセージが表示され、アプリが異常終了せずに継続操作できることを確認します。

### 準備（使うファイル）
- `corrupt.png`（破損画像）
- `corrupt.pdf`（破損 PDF）
- `encrypted.pdf`（閲覧パスワード付き PDF）
- `restricted.pdf`（閲覧制限のみの暗号化 PDF）
- `too-many-pixels.png`（画素数上限超過画像）
- `too-many-pages.pdf`（ページ数上限超過 PDF）
- `mixed_sizes.pdf`（300 dpi で描画上限超過となるページを含む PDF）
- 書き込み権限のない保存先フォルダ（後述の手順で作成）

### 操作と期待する結果

#### 1. 破損ファイルの読み込み

##### 「画像 → PDF」での破損画像

`corrupt.png` はヘッダーより後ろが壊れている。追加のときはヘッダーだけを読むので、壊れていることは、画素を読む変換のときに分かる（design §4.1）。

- **`corrupt.png` のみを追加した場合**:
  - 追加したときは、エラーにならず通常の行として一覧に入る（サムネイルは出ず、画像のアイコンになる）。
  - 下部バーの左側に「1 ページの PDF になります」（「1 枚ずつ」の場合は「1 個の PDF を保存します」）と表示され、保存・変換ボタンは押せる。
- **正常な画像（`photo.jpg`）と共に追加して、「1 枚ずつ」で変換した場合**:
  - `corrupt.png` の行の状態が赤字で「✕ 失敗」、理由が「画像を読み込めませんでした。ファイルが壊れている可能性があります」になる。
  - `photo.jpg` の行は「✓ 完了」になり、保存先には `photo.pdf` だけができる。
  - 上部バナーに「変換が終わりました：成功 1 件 · 失敗 1 件」、下部バーに赤字で「✕ 失敗があります」と表示される。
- **同じ 2 つを「1 つの PDF」で保存した場合**:
  - `corrupt.png` の行に「✕ 失敗」と同じ理由が表示され、`corrupt.png` を除いた 1 ページの PDF が保存される。
  - 上部バナーに「変換が終わりました：成功 1 件 · 失敗 1 件」と保存したファイル名、下部バーに赤字で「✕ 失敗があります」と表示される。

##### 「PDF → 画像」での破損 PDF
- `corrupt.pdf` を単一で追加する。
  - **期待結果**: 単一 PDF モードになり、見出し部分に赤字で「✕ 読み込めません」が表示され、サムネイル一覧の領域にエラーメッセージ「PDF を読み込めませんでした。ファイルが壊れている可能性があります」が表示される。「変換を開始」ボタンは無効化されて押せない。
  - ※なお、複数 PDF モード（表形式）で追加した場合は、表の該当行の状態に「✕ 読み込めません」、理由に「PDF を読み込めませんでした。ファイルが壊れている可能性があります」が表示される。

#### 2. 暗号化・パスワード保護された PDF
- `encrypted.pdf` を追加する。

## 項目 8: 外部通信の確認（通信が発生しないことの確認）

要件: NFR-01、design §9。アプリが外部ネットワークと一切通信しないこと（プライバシー保護）を確認します。

### 操作

#### Windows

`msedgewebview2.exe` は Teams や Outlook など、ほかのアプリも使うので、名前だけで見るとほかのアプリの通信が混ざる。PDF Converter の WebView2 は、データの場所（`%LOCALAPPDATA%\com.w034ff.pdfconverter\EBWebView`。`com.w034ff.pdfconverter` は `src-tauri/tauri.conf.json` の `identifier`）をコマンド行の `--user-data-dir` に持つので、それで選び出す。起動直後の通信はすぐ終わることがあるので、1 秒ごとに記録し続ける。

1. PDF Converter を閉じた状態で、PowerShell で次を実行する（2 分間記録する）。
2. 実行が始まったらすぐに PDF Converter を起動し、画像の追加、PDF の変換などの一連の操作を行う。
3. 2 分たつと、外への TCP 接続の一覧（`<プロセス名> <IP アドレス>:<ポート>`）が出る。

```powershell
$seen = @{}
$end = (Get-Date).AddSeconds(120)
while ((Get-Date) -lt $end) {
  $ids = @(Get-CimInstance Win32_Process -Filter "Name='pdf-converter.exe' OR Name='msedgewebview2.exe'" |
    Where-Object { $_.Name -eq 'pdf-converter.exe' -or $_.CommandLine -match 'com\.w034ff\.pdfconverter' } |
    ForEach-Object { $_.ProcessId })
  Get-NetTCPConnection -ErrorAction SilentlyContinue |
    Where-Object { $ids -contains $_.OwningProcess -and $_.RemoteAddress -notin '0.0.0.0', '::', '127.0.0.1', '::1' } |
    ForEach-Object {
      $name = (Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue).ProcessName
      $seen["$name $($_.RemoteAddress):$($_.RemotePort)"] = $true
    }
  Start-Sleep -Seconds 1
}
$seen.Keys | Sort-Object
```

4. `msedgewebview2` の行が出たら、その IP アドレスの持ち主を調べる（WebView2 は Windows の DNS のキャッシュを通さずに名前を解決することがあるので、`Get-DnsClientCache` では名前が分からないことがある）。調べる相手は ipinfo.io で、送るのは IP アドレスだけ:
   ```powershell
   Invoke-RestMethod "https://ipinfo.io/<IP アドレス>/org"
   ```
5. この方法で見えるのは TCP の接続だけなので、リソース モニター（`resmon.exe`）の「ネットワーク」タブの「ネットワーク アクティビティのあるプロセス」で、`msedgewebview2.exe` の送受信も合わせて見る。

#### Linux
1. アプリを起動し、各種変換操作を行う。
2. 端末で以下のコマンドを実行し、アプリ本体およびワーカー（同一実行ファイル `pdf-converter`）、画面表示プロセス（WebKitGTK）のネットワークソケットを確認する:
   ```bash
   ss -tunp | grep -E "pdf-converter|WebKit"
   ```
3. `pdf-converter`（本体およびワーカー）、`WebKitNetworkProcess`、`WebKitWebProcess` について、外部の IP アドレスに対する TCP / UDP 接続が一切表示されないことを確認する（ローカルの IPC 通信のみであること）。

### 期待する結果
- Windows: `pdf-converter` の行が 1 つも出ない（本体とワーカーは外に接続しない）。`msedgewebview2` の行は、持ち主が Microsoft（`AS8075 Microsoft Corporation`）なら、README に書いた WebView2 ランタイム自身の通信として例外に記録する。Microsoft 以外への接続があれば不具合として記録する。
- Linux: アプリ本体、ワーカープロセス、および WebKit 表示プロセスが外部のサーバーへ一切接続を行っていないこと。
